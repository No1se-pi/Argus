# Полная презентация Argus

Функция разрабатывается в ветке `dev`. Рабочий шаблон — исходная 29-страничная презентация «Отзывы и Активность 19.10.26.pptx». Код не содержит копии шаблона или персональных данных.

## Использование

1. Загрузить исходник через ВК → «Шаблон презентации». Он используется также для полного отчёта.
2. В меню ВК или отзывов открыть «Полная презентация» и выбрать период. Другой вариант: `/activity_pptx 12.10.2026 19.10.2026`.
3. Дождаться подготовки. Если в базе недостаточно истории отзывов, генератор последовательно догружает её. Старые записи не создают уведомления; новые записи, попадающие в рабочее окно мониторинга, остаются в очереди анализа.
4. Бот отдаёт `activity.pptx` и `audit.zip`. При сетевой ошибке использовать «Повторить отправку»: это передаёт сохранённые файлы без повторного сбора.

Оба дня периода включаются по часовому поясу бота, по умолчанию Москва. Будущие даты не принимаются.

## Состав

- Обложка, рейтинги и сводки по учебным отделениям для Яндекса и 2ГИС.
- Все отзывы за период, независимо от тональности. Ограничение «только негативные» относится к уведомлениям, а не к презентации.
- Карточки HTML/CSS с автором, датой, текстом и фактическими звёздами. Аватарки и дополнительные подписи о способе изготовления не добавляются. Длинный текст переносится на отдельные слайды, а не обрезается.
- Пять таблиц ВК с исходными ФИО. Если сохранённый сбор за более широкий период полностью покрывает выбранный, лайки пересчитываются по детализации постов. ВК для этого не запрашивается. Нет покрытия — значения «н/д», а не нули.
- Критические случаи, подтверждённые администратором через «Подтвердить». Непроверенное предположение LLM не публикуется как установленный критический случай. Сейчас доступны текст и ссылка; медиа исходных сообщений отдельно не архивируются.

Используются фон, шапки и элементы оформления исходника. Число слайдов динамическое, поэтому не обязано равняться 29. Старые слайды, карточки, изображения и заметки удаляются из пакета PPTX по графу связей, а не закрываются поверх новым изображением. Карточки имеют кликабельные ссылки на источник.

## Сверка

`audit.zip` содержит:

| Файл | Назначение |
| --- | --- |
| `reviews.csv` | Площадка, отделение, автор, оценка, дата, полный текст, ссылка, идентификатор |
| `vk-matches.csv` | Исходные ФИО и числа, результат сопоставления и новые лайки |
| `identity-suggestions.csv` | Возможные профили для ненайденных/неоднозначных ФИО, основания и ссылки для ручной проверки |
| `checks.csv` | Понятная таблица покрытия источников, наличия рейтингов и ограничений |
| `evidence.json` | Снимок данных, периоды, покрытие, исходная детализация ВК и предупреждения |
| `manifest.json` | Период, время подготовки, число слайдов/отзывов и ограничения |

Предположения не становятся автоматическими привязками. В частности, транслитерация фамилии без имени или похожий ник не доказывают личность. После проверки пользователь может сохранить привязку штатной командой `/vk_likes_bind`.

CSV отзывов экранирует начало потенциальных формул Excel; оригинальный текст сохраняется в JSON. Все выгрузки остаются в игнорируемом `data/exports/activity/<ID>/`, доступны через бота только администраторам и не публикуются на сайте.

## Ограничения данных

- Неопубликованные отзывы «на модерации» нельзя получить из публичной выдачи. Они не выдумываются и не копируются из старого шаблона.
- Отзывы могли быть удалены, изменены или опубликованы после подготовки исходника. Текущий отчёт не является архивным снимком сайта на старую дату.
- Яндекс отдаёт `updatedTime`; дата на карточке соответствует данным площадки. Исходная дата до редактирования в этом интерфейсе не предоставляется.
- Рейтинги берутся только из подтверждённого ответа площадки и сохраняются с датой замера. Для изменения рейтинга нужны замеры до начала и до конца периода. Если исторических замеров нет, выводится «н/д», а не среднее звёзд или старое число из шаблона. Извлечение рейтинга Яндекса зависит от наличия соответствующих структурированных данных страницы.
- CAPTCHA, 429, блокировка, повтор страницы или предел пагинации означают неполное покрытие, а не «0 отзывов». Неполная сводка показывает «н/д»/нижнюю границу; подробности — в сверке. Автоматического решения CAPTCHA нет.

## Устройство и эксплуатация

- `app/reports/data.py`: отдельное соединение SQLite с согласованным read-only снимком, календарные границы и пересчёт ВК.
- `history.py`: дозагрузка не более 40 страниц на источник, паузы, дедупликация и подтверждение покрытия. 2ГИС использует `offset_date` из `meta.next_link`, а не фиктивный `page`.
- `render.py`: один Chromium на экспорт, пакетное измерение карточек, все сетевые запросы при рендере запрещены, HTML-текст экранируется.
- `pptx.py`: повторное использование оформления, сборка OOXML и удаление неиспользуемых частей пакета.
- `service.py`: последовательная генерация, сохранение результатов и комплект сверки. `manifest.json` записывается последним.
- `app/bot/activity.py`: кнопки, даты, отправка и повторная отправка готового результата.

Установка на сервере:

```powershell
python -m pip install -e ".[reports]"
python -m playwright install chromium
```

На Linux для Chromium должны быть установлены системные зависимости (`python -m playwright install --with-deps chromium`). Генератор не требует PowerPoint: PowerPoint использован только при проверке результата на ноутбуке.

Защитные пределы: период до года, 500 отзывов, 100 подтверждённых случаев, 250 слайдов, готовый PPTX до 40 МБ; превышение даёт явную ошибку. Для больших объёмов выбирать более короткий период.

## Telegram: история и графики

Статистика считается по дате сообщения, а не загрузки. «Сегодня» может быть пустым сразу после импорта старых сообщений. Добавлена «Вся загруженная история». Графики за 30 дней строятся непосредственно по сообщениям/анализу с локальными календарными датами, без зависимости от кеша дневного дайджеста. Исторические сообщения попадают в статистику, но не создают старых уведомлений.

## Проверка на исходных данных

Для 12–19 октября 2026 из последнего 30-дневного снимка ВК выделились ровно 17 постов. После дозагрузки публичной истории получены 47 отзывов Яндекса и 9 отзывов 2ГИС, полное покрытие начала периода по 12 источникам. Результат — 33 слайда, около 3,6 МБ; файл открыт в PowerPoint и экспортирован в PDF для визуальной проверки. Числа отличаются от исходных 43/8 и не подгоняются под старую презентацию.

На сервере подтверждены 149 проанализированных Telegram-сообщений; графики за последние 30 дней учитывают 143 сообщения (часть истории старше окна). Отправка тестовых уведомлений пользователям не выполнялась.

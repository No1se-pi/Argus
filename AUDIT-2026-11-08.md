# Аудит Argus: Telegram, отзывы и PPTX — 08.11.2026

## Правила обработки

- Telegram: локальная LLM оценивает содержание и контекст. Алерт при риске уровня 2–3: угрозы, целевое унижение/оскорбление администрации, намеренная порча оборудования, кража, продажа/реклама запрещённых веществ и другие категории безопасности. Обычная критика сама по себе не повод для алерта.
- Яндекс Карты / 2ГИС: отдельная классификация positive/negative; алерт только для нового негативного отзыва. Текст важнее звёзд. Если текста нет, модель использует оценку. Первое получение истории создаёт тихую базовую линию.
- Решение модели требует проверки человеком; оно не подтверждает факт нарушения.

## Найдено и исправлено

| Проблема | Изменение |
| --- | --- |
| Отзывы отправлялись без оценки LLM, включая позитивные | Отдельный ReviewClassifier, сохранение результата, версии промпта и модели; позитивные исключены из очереди отправки |
| При недоступной/некорректно ответившей LLM могла теряться ясность состояния | Отзыв остаётся в очереди, ошибка записывается, повтор анализа не раньше пяти минут; автоматической подмены оценки нет |
| На сервере OLLAMA_MODEL был пустым, localhost внутри botvpn не указывал на host Ollama | Выбрана установленная qwen3:1.7b, настроен отдельный HTTP-прокси к хосту, тайм-аут 120 с, последовательные запросы к модели |
| В рабочей серверной базе не было Telegram-источников | Добавлены два публичных канала и уже доступный сессии закрытый чат, проверено чтение каждого |
| Публикации без событий Telethon могли обходить LLM | Дополнительный опрос раз в минуту, отдельный курсор анализа, дедупликация, соблюдение FloodWait |
| Загруженная для статистики история могла задерживать анализ новых сообщений | Живые сообщения имеют приоритет перед историей в очереди LLM |
| Лимит одной порции мог пропускать новые сообщения | Живой опрос читает от старых к новым, при заполненной порции продолжает с последнего полученного сообщения |
| Старый Telegram-планировщик отправлял все новые сообщения до анализа | При включённом анализе рисков эти уведомления отключены; решения принимает очередь LLM |
| Ошибка отправки Telegram-алерта не приводила к повторной доставке | Сохраняемая очередь по каждому адресату; подтверждённо доставленные адресаты не получают повторов, неотправленные повторяются после задержки и перезапуска |
| Обработчики встроенного TimeoutError не соответствовали asyncio.TimeoutError в Python 3.10 | Исправлены ожидания планировщиков |
| Кнопка состояния LLM не выводила экран; загрузка истории обращалась к неопределённым переменным | Код экрана перенесён в правильный обработчик, обе кнопки проверены отдельно |
| Пользователь видел проблему PPTX как неудачную загрузку шаблона | Исходный шаблон корректен и уже был сохранён на сервере: 5 098 031 байт. Подтверждённая ошибка — тайм-аут передачи готового файла в Telegram |
| Слишком короткие сроки передачи PPTX | Загрузка/отправка до 300 с; сетевые ошибки перехватываются, шаблон и отчёт сохраняются, готовые PPTX и CSV записываются в data/exports перед отправкой |

## Проверки

- Исходный PPTX проходит разбор и заполнение; ФИО и оформление сохраняются, спорные совпадения попадают в отдельный CSV.
- Автоматические тесты: 186 в основной кодовой базе; 190 на сервере с сохранёнными дополнительными проверками и локальными доработками сервера.
- Проверены отказ LLM с повторным анализом, отсутствие алертов для позитивных отзывов, отсутствие повторной классификации уже оценённых отзывов, сохранение файлов презентации, тихий старт, независимый курсор и повтор доставки после перезапуска.
- Из botvpn выполнены реальные чтения первой страницы Яндекса и 2ГИС: HTTP 200, по три отзыва; никаких тестовых уведомлений адресатам не отправлялось.
- На серверной qwen3:1.7b проверены восемь синтетических случаев: позитивный отзыв, жалоба, отрицание негативной оценки, смешанный отзыв с жалобой; обычная критика, унижение администрации, намеренная порча мониторов, реклама запрещённых веществ. Итоговые классы соответствовали ожиданиям. Это небольшая функциональная проверка, не измерение точности модели на реальном потоке.

## Эксплуатация и ограничения

- Telegram продолжает работать через VPN. Для Ollama и карт используется отдельный маршрут; проверка TLS не отключается.
- Кнопка «PPTX из отчёта» использует сохранённые данные и не запрашивает ВК заново. Передачу реального файла в Telegram после исправления ещё нужно подтвердить нажатием этой кнопки.
- Токены, cookie, сессии и выгрузки не включаются в коммит; резервные копии и результаты находятся вне Git.
- Текстовые сообщения/подписи анализируются; OCR изображений и распознавание голосовых не реализованы. Комментарии в отдельных Telegram-группах обсуждения требуют добавления соответствующей группы в источники.
- Публичные интерфейсы карт могут меняться или выдавать CAPTCHA/429; при отказе сохраняется ошибка и включается отсрочка, отсутствие ответа не считается отсутствием отзывов.
- При сетевом тайм-ауте после фактической доставки Telegram может не подтвердить результат. В этом случае повтор способен создать дубликат: гарантировать exactly-once поверх Telegram API нельзя.
- Истёкшее подтверждение Telegram callback больше не прерывает обновление экрана меню.
- Короткий промежуток между сохранением анализа и постановкой алерта в очередь пока не объединён общей транзакцией. Аварийное завершение именно в этот момент остаётся отдельным риском.
- Периодические блокировки ВК этим обновлением не исправляются.

## Проверка пользователем

1. В меню ВК открыть сохранённый отчёт → «PPTX из отчёта»: должны прийти презентация и CSV сверки.
2. В меню отзывов проверить модель, состояние источников и очередь анализа; новые позитивные отзывы не должны вызывать алерт.
3. При ошибочной оценке Telegram использовать «Ложное»; примеры нужны для дальнейшей калибровки, обратная связь не переобучает модель автоматически.

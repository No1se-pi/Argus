Сохраняйте исходные незакоммиченные изменения и работайте в отдельной ветке. Не делайте force-push, не подменяйте стабильную ветку и не развёртывайте обновления без соответствующей задачи.

Обновление из старой локальной папки потеряло бы эту функцию. Не копируйте в Git `.env`, `secrets/`, SQLite, сессии, логи и резервные копии.

## Ключевая логика

- `app/reviews/client_yandex.py`: сессия и CSRF, до четырёх попыток API; повторы для 500/502/503/504 с паузами 1/2/4 секунды. Обновление сессии разрешено один раз за запрос, в том числе после временного сбоя. 429 не повторяется немедленно. **HTML fallback отключён:** кэш старый, сортировка и полнота не гарантированы. Он не должен выдавать SUCCESS и продвигать состояние догрузки при недоступном API.
- `app/reviews/service.py`: baseline без рассылки старых отзывов, дедупликация, догрузка страниц, доставка, backoff. При исчерпании лимита без достижения конца новые отзывы не сохраняются как известные; источник сообщает ошибку с просьбой увеличить `REVIEWS_MAX_CATCHUP_REVIEWS`. Это требует вмешательства при большом разрыве. Уведомление о восстановлении отправляется после завершения догрузки.
- `app/reviews/analyzer.py`: отдельный воркер Gemini, результаты в `review_ai_analyses`.
- `app/alerts/service.py`: тихая доставка только SUCCESS + GREEN + ровно 5 звёзд. 4 звезды, YELLOW/RED и неуспешный анализ остаются с обычным уведомлением. `REVIEWS_SILENT_GREEN=false` отключает тихий режим.

## Что установлено и что не доказано

В ходе аудита VPS был active, в SQLite было 686 отзывов, 0 неотправленных записей, 0 дубликатов ID и 152 успешных AI-анализов. Baseline также помечается отправленным: по одному флагу нельзя утверждать, что каждый исторический отзыв реально ушёл в чат.

Изолированная живая проверка исправленного клиента получила 500 на четырёх из шести источников Яндекса. На двух успешных источниках получено по 10 отзывов, все ID есть в SQLite. Полная сверка недоступных источников невозможна. Утверждения «ничего не пропущено» и «точно обновилась балансировка Яндекса» доказательств не имеют.

## Проверка перед релизом

1. Запустить `python -m pytest -q` в изолированном checkout без боевого `.env`.
2. Проверить живой API всех источников и свежесть их `last_success_at`.
3. Сверить ID отзывов за время сбоя; не сбрасывать счётчики и backoff ради зелёного статуса.
4. Сохранить резервную копию SQLite через SQLite backup API перед настоящим deploy.
5. Переносить проверенные коммиты целиком, включая тихие уведомления и тесты.

Проверка и исправление кода сами по себе не означают, что версия развёрнута на VPS.
